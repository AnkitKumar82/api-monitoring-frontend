# Incidents Page Specification

## Overview

Build a professional **Incidents** page for the API Monitoring SaaS dashboard.

The purpose of this page is to help users quickly answer:

- What broke?
- When did it break?
- Is it still broken?
- How long did it remain unavailable?
- Which regions were affected?
- Who was notified?

This page should feel similar to commercial monitoring platforms such as Better Stack, UptimeRobot, Pingdom, Datadog, and StatusCake.

---

# Design Requirements

## MUST

- Follow the existing design system
- Use existing custom components (CTypography, GlassCard, Buttons, etc.)
- Follow existing color palette
- Reuse CSS variables
- Keep spacing consistent
- Responsive layout
- Support Dark & Light themes
- Use subtle hover animations
- Use realistic mock data
- Do not introduce a new design language
